## Direct answers to your six checks

**(a) M3 `md` = Material Design: ⚠️ partially verified.** Verified: every M3 token path begins with `md`, then `ref` / `sys` / `comp` (`md.ref.palette.secondary90`, `md.sys.color.on-secondary`, `md.comp.fab.primary.container.color` appear as comments in Google's own token files, `tokens/versions/latest/sass/*.scss` in material-web). The CSS form is `--md-sys-color-<token>` and material-web docs say: "unlike `--md-ref-*` and `--md-sys-*` tokens, which are prefixed with `ref` and `sys`, component tokens are *not* prefixed with `comp`." NOT found anywhere readable: a sentence that expands "md" to "Material Design" (that wording lived on m3.material.io, unreachable). Treat "md = Material Design" as consistent with all evidence but not quoted.

**(b) Tailwind default breakpoints: ✅.** `theme.css` (tailwindcss main): `--breakpoint-sm: 40rem; --breakpoint-md: 48rem; --breakpoint-lg: 64rem; --breakpoint-xl: 80rem; --breakpoint-2xl: 96rem;`. The docs table adds px: 640 / 768 / 1024 / 1280 / 1536, as `@media (width >= 40rem)` etc., and `max-*` variants as `@media (width < 40rem)`. Docs: "There are five breakpoints by default, inspired by common device resolutions."

**(c) DTCG: ✅ and status corrected.** `$value`, `$type`, `$description` confirmed in `format/design-token.md`; alias syntax `"$value": "{colors.blue}"` (curly braces reach only complete tokens; `$ref` JSON Pointer reaches properties) in `format/aliases.md`; "This spec considers the terms "alias" and "reference" to be synonyms". Status: the 2025.10 snapshot is headed **"Final Community Group Report 28 October 2025"** (`www/src/pages/TR/2025.10/format/index.html`), and DTCG's own index (`www/src/pages/technical-reports.md`) lists `2025.10 | Stable | 2025-10-28`, with the unversioned `/TR/drafts/` listed as "Preview | Experimental". It is a W3C Community Group report, not a W3C Recommendation. Canonical URL: https://www.designtokens.org/TR/2025.10/format/ (my first pass linked `/tr/drafts/`, the experimental preview).

**(d) shadcn background/foreground: ✅.** theming.mdx: "We use semantic background and foreground pairs. The base token controls the surface color and the `-foreground` token controls the text and icon color that sits on that surface." and "The background suffix is omitted for the surface token. For example, `primary` pairs with `primary-foreground`."

**(e) Figma Variables (plugin-typings): ⚠️ structure verified, prose not.** Typings confirm `VariableCollection` (`modes: Array<{modeId, name}>`, `defaultModeId`, `variableIds`, `isExtension`, `extend()` limited to Enterprise), `Variable` (`resolvedType`, `valuesByMode`, `scopes`, `codeSyntax` for WEB/ANDROID/iOS) and `VariableAlias { type: 'VARIABLE_ALIAS', id }`. The typings contain no prose definitions such as "a collection is a set of variables and modes"; that wording is Help Center only (unreachable). Resolved data types are six: BOOLEAN, COLOR, EASING, FLOAT, STRING, TIMING.

**(f) Primer `fgColor` / `bgColor` and muted vs subtle: ✅.** `fgColor.json5`, `bgColor.json5`, `borderColor.json5` exist as functional tokens; token-names.mdx: "`muted` - The secondary color variant for a given token." and "`emphasis` - The opposite of "muted", emphasis is a stronger color variant." migrating.mdx: legacy `fg.subtle` -> "eliminated, use `--fgColor-muted` instead", `border.subtle` -> eliminated, `canvas.subtle` -> `--bgColor-muted`, `accent.subtle` -> `--bgColor-accent-muted`. So legacy "subtle" was folded into "muted" (or removed). Note `fg.muted` already existed in the legacy names.
