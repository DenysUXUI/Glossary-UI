# Typography terms: vetted candidates for Katalog UI (EN · PL · UA)

Researched 2026-10-16 for the Typography section (currently L-01…L-16 + H-12 + B-03).
Scope: terms a working product/UI designer needs that the app does not yet cover.

## How this was verified (read first)

- The documentation websites (fonts.google.com, m3.material.io, m2.material.io, developer.mozilla.org, w3.org, learn.microsoft.com, help.figma.com, getbootstrap.com, tailwindcss.com, unicode.org, support.apple.com) were **not reachable** from this container. WebSearch only returns titles and URLs, so nothing was taken from search snippets.
- Every term below was read in the **primary source files** of the allowed publishers instead: MDN `mdn/content`, W3C `w3c/csswg-drafts` and `w3c/wcag`, Bootstrap `twbs/bootstrap` (tag v5.3.3), Tailwind `tailwindlabs/tailwindcss.com`, Microsoft Style Guide `MicrosoftDocs/microsoft-style-guide`, Figma `figma/plugin-typings`, Material `material-components/*` + `androidx/androidx` + npm `@material/web@2.5.0`, Unicode `unicode-org/cldr` + `unicode-org/unicodetools`, and Apple HIG / SwiftUI JSON from developer.apple.com (reachable directly).
- Human-facing URLs in the tables are **derived from each file's slug/path** (front matter or repo path), not opened in a browser. The exact raw path for each label is in the **Source key** at the end.
- **Quotes were machine-checked verbatim** against the downloaded files: 218 quotes in the checker list, 0 failures, each 25 words or fewer. A second pass over the markdown found every quoted string in the corpus except one Apple sentence that is split by a link node ("Using [title-style capitalization], consider starting the label with a verb"), which I confirmed by hand in the JSON. In quotes, backticks and markdown bold were dropped and whitespace collapsed. Scripts: a checker script in the session scratchpad (not kept) and `md_quote_check.py`; downloaded sources are kept (grep only, never executed) in the session scratchpad (not kept).
- W3C specs were read from the **Editor's Drafts** (`main` branch), which can differ from the dated TR snapshots the links point to.
- **Status**: ✅ term/definition found verbatim in at least one official source · ⚠️ partial (name found, definition or key aspect missing) · ❌ not found (listed only under "Not verified / dropped").
- **Confidence**: high = 2+ independent official sources · med = 1 · low = weak.
- Polish names are deliberately not included: no allowed source gives them, and the brief says not to invent. Add PL in the app after a Polish-source pass.

**Totals: 50 candidate rows (23 must, 27 nice). Status: 48 ✅, 2 ⚠️. A further 17 items are ❌ and listed under "Not verified / dropped".** This is above the 30–40 target; dropping the 10 rows named in the "Cut-first list" (see Ranking) lands at 40.

## Confusions worth a "Co jest co?" card

Each line is one distinction that the cited source supports.

1. **Caption vs Label vs Footnote vs Overline.** Caption "annotate[s] imagery" (M2); Label is component text and its Large size is the button text (M3 KDoc); Footnote is Apple's 13pt style and HTML `<small>` is "small print"; Overline "introduce[s] a headline" and is uppercase (M2).
2. **Headline: Apple vs M3 vs M2.** Apple Headline = one 17pt Semibold style; M3 Headline = 32/28/24sp; M2 Headline = six sizes, 96 to 20px.
3. **Title vs Headline.** In Apple, Title (28–20pt) is larger than Headline (17pt); in M3, Headline (32–24sp) is larger than Title (22–14sp).
4. **Label (type role) vs label (component) vs form-field label.** M3 role vs Apple HIG "static piece of text" vs B-03.
5. **Overline (type role) vs overline (decoration).** M2 role is uppercase text above a headline; CSS `overline` is "a decorative line above" text.
6. **Sentence case vs Title case.** Microsoft: sentence-style for UI labels incl. buttons; Apple HIG: title-style for buttons and menu items, but also "Choose a style for each UI element type and use it consistently throughout your app".
7. **Capitalize vs Title case.** CSS `capitalize` raises every word's first letter; it "does not create title casing".
8. **Uppercase vs Capitalize vs Small caps.** `uppercase` = all characters capital; `capitalize` = first letter of each word; `small-caps` = alternate glyphs (`smcp`) that "use the form of uppercase letters but are displayed using the same size as lowercase letters".
9. **Italic vs Oblique.** Italic is a cursive-leaning face; oblique is "just sloped versions of the regular face"; either can be faked by the browser.
10. **Strikethrough `<s>` vs `<del>`.** `<s>`: "no longer relevant or no longer accurate"; `<del>`: text "deleted from a document" (an edit).
11. **Hyphen vs en dash vs em dash vs minus.** Hyphen joins words; en dash = ranges; em dash = parenthetical; Unicode keeps a separate MINUS SIGN (U+2212).
12. **Straight vs curly vs Polish quotes.** Polish is „ ” with nested « » (CLDR), not “ ”; Microsoft allows straight quotes online.
13. **Space vs non-breaking space vs soft hyphen.** NBSP never breaks; soft hyphen U+00AD is invisible until a break is needed.
14. **Serif / sans-serif / monospace vs system-ui.** The first three describe letterform; `system-ui` means "whatever the OS uses" and is not for long paragraphs.
15. **Font weight vs emphasized style.** Weight is a value (L-07); Apple's "emphasized" variants are a per-style heavier weight (medium to heavy).
16. **Balance vs pretty wrap.** `balance` evens line lengths on a few lines; `pretty` improves breaks over many lines.

Not available as a source-backed card: **legibility vs readability** (see below).
