## Unverified suspicions (no browser available)

1. `setPointerCapture` on the whole card for any non-`input/button/a` pointerdown: in Chromium the following `click` is retargeted to the capturing card, so clicking a demo `<label>`/switch (`<i>`) inside `.qstage` would not toggle; dragging inside the demo `<textarea>`/`<select>` (1 and 2 exist in DATA) starts a swipe because those tags are not in the guard.
2. No `scrollTo(0,0)` between cards (only on tab change): after a long reveal that was scrolled, the next card may open mid-page on small phones.
3. Typed input `keydown Enter` ignores `ev.isComposing` (IME / Android predictive keyboards could submit mid-composition).
4. A2HS "full screen" claim: no manifest / `apple-mobile-web-app-capable` / apple-touch-icon in `<head>` - probably opens in the browser chrome.
5. Export via detached `<a download>` + never-revoked `createObjectURL` may misbehave in iOS standalone/webview; minor leak otherwise.
6. `pointercancel` after the browser grabs a vertical pan with dx already >= 78 px would still fly the card out.
7. Quitting the pick phase after right-swipes leaves those terms in box 1 / due-now without ever being studied (they appear under "Powtórka" as "1. powtórka"). Probably acceptable, but it contradicts "Powtórka = already learned".
8. Placeholder colour `#95A09A` on white is ~2.7:1 (below 4.5:1) in `#q`.
